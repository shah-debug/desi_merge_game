# Desi Merge: Audio System Audit and Fix (Phase 6.6)

## Root cause

**There was no `AudioListener` in any scene.** In the YAML, `Bootstrap.unity`, `MainMenu.unity` and `Gameplay.unity` each contained one Camera and zero AudioListeners. Unity renders sound only through an enabled AudioListener, so every `AudioSource.Play()` succeeded silently.

How it happened: the scenes are generated by code (`FoundationSetup`, `MainMenuSceneBuilder`, `GameplaySceneBuilder`), which build cameras with `AddComponent<Camera>()`. Only Unity's "New Scene" template adds a listener next to the camera. The earlier audio tests verified clip assignment, routing and volume numbers, which were all correct, but nothing verified that a listener existed.

## Fix

- `AudioService` makes sure its host has exactly one `AudioListener`. The host is the bootstrapper's `DontDestroyOnLoad` object, so there is one listener for the whole session, unaffected by scene changes. The scene cameras still have none, so Unity never warns about two listeners.
- When a scene is played directly in the Editor (development services), the listener sits on that scene's own audio host and is destroyed with the scene.

## Everything else checked

| Area | State |
|---|---|
| AudioSources | 1 music (loop) and an SFX round-robin pool (now 8 voices), 2D, `playOnAwake` off, created once on the host |
| AudioMixer | None in the project; volume is per source (`clip volume × channel volume`, or 0 when muted). Intentionally unchanged. |
| Settings → playback | `ISettingsService.Changed` → `ApplyVolumes()`, so slider and mute changes apply on the same frame |
| Persistence | `settings.json` (schema 3); restored at startup before any sound plays; saved when the Settings panel closes and on pause/quit |
| Scene changes | Same host and same music source; the same track is not restarted; the menu and gameplay each request their own track |
| Pause | Gameplay pause pauses the music in place and plays the pause cue; resume continues it. SFX are not paused (short). |
| App interruptions (Android) | Unity pauses its audio output when the app loses focus; gameplay additionally pauses (existing `OnApplicationPause`/`OnApplicationFocus`). **Not verified on a device.** |
| Missing clips | `PlaySfx`/`PlayMusic` stay silent and log one warning per cue (development aid); no exceptions |
| Duplicate playback | Each event plays its cue once (one subscription per loop); taps play through `ButtonFeedback` only |
| Import | SFX: ADPCM, decompress on load, **preload on** (new); music: Vorbis, compressed in memory, load in background |

These prove the routing and the listener. **They cannot prove that sound is audible:** batch mode has no audio device, and no human listened.

## Manual audio checklist (Editor, then a phone)

1. Open `Bootstrap.unity`, press Play, make sure the Game view's **Mute Audio** is off and the PC volume is up. Menu music starts.
2. Tap any button: a short click.
3. Settings: drag Music to 0, and the music fades out at once; back up, and it returns. Mute Music, and it is silent; unmute. Repeat with Sound Effects (tap a button to hear it).
4. Stop and press Play again: the slider and mute values are kept.
5. Play: you hear the drop, the merge (higher pitch for bigger items), Hammer/Shuffle use, pause/resume, and the new-best or game-over sound.
6. Menu → Daily Rewards → Claim: the reward sound plays with the popup.
7. On Android: lock the phone during play, then unlock (the game is paused, the music resumes after Resume); take a phone call or play a YouTube video (the game should not fight for audio); press Home, then return.
